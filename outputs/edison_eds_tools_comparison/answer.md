## 2. Tool-by-Tool Assessment

### 2.1 eXSpy/HyperSpy (Python)

**Best use case:** Per-pixel processing and analysis of spectrum-image (SI) datacubes, particularly for (S)TEM-EDS. HyperSpy was originally a monolithic Python library for multi-dimensional data analysis in electron microscopy; the EDS/EELS quantification functionality has been refactored into a dedicated extension package called eXSpy (moreira2022quantitativemeasurementof pages 1-7, moreira2023agsurfacesegregation pages 5-10).

**Strengths:** HyperSpy/eXSpy operates natively on numpy arrays and integrates directly with the broader Python scientific ecosystem (scipy, scikit-learn, scikit-image, matplotlib). It provides built-in principal component analysis (PCA) and non-negative matrix factorization (NMF) for denoising and blind source separation of spectrum images (moreira2023agsurfacesegregation pages 5-10). For TEM-EDS, it implements the Cliff–Lorimer k-factor method, which has been used in published quantitative studies of bimetallic nanoparticles (moreira2023agsurfacesegregation pages 5-10). It is the strongest of the three tools for automated, large-scale per-pixel spectral processing and is widely used for STEM-EDS quantitative mapping (moreira2022quantitativemeasurementof pages 1-7).

**Weaknesses/Limitations:** HyperSpy/eXSpy does not include a validated, built-in ZAF or φ(ρz) matrix correction engine for bulk SEM-EDS quantification, which limits its applicability for the standards-based k-ratio protocol central to rigorous SEM microanalysis (newbury2019electronexcitedxraymicroanalysis pages 1-2, goldstein2018quantitativeanalysisthe pages 1-4). Published accuracy benchmarks comparable to Newbury & Ritchie's RDEV studies for DTSA-II do not appear to exist for HyperSpy's EDS quantification. Its Cliff–Lorimer approach is appropriate for thin specimens (TEM) but does not account for the absorption and fluorescence corrections required for bulk samples.

**Costs:** Free and open source (Apache/BSD-style license). Computationally efficient for vectorized datacube operations but can demand substantial RAM for very large SI datasets. Requires familiarity with Python and package management (conda/pip), which presents a learning curve for users accustomed to GUI-based microanalysis software. Cross-platform (Windows/macOS/Linux).

### 2.2 NIST DTSA-II (Java)

**Best use case:** Rigorous, standards-based bulk-specimen SEM-EDS quantitative analysis following the k-ratio/matrix correction protocol, including quantitative compositional mapping of spectrum images (newbury2019electronexcitedxraymicroanalysis pages 1-2, goldstein2018quantitativeanalysisthe pages 1-4).

**Strengths:** DTSA-II implements multiple linear least squares (MLLS) peak fitting using experimentally measured peak references, enabling robust deconvolution of overlapping peaks and inspection of peak-fitting residual spectra to detect hidden constituents (newbury2019electronexcitedxraymicroanalysis pages 3-4, newbury2019electronexcitedxraymicroanalysis pages 20-22). It employs the XPP φ(ρz) matrix correction algorithm (Pouchou & Pichoir, 1991) as its default, using the Chantler FFAST mass absorption coefficient (MAC) database (Z ≤ 92) supplemented by Sabbatucci coefficients (newbury2024testingtheaccuracy pages 16-18). DTSA-II has the most extensive published accuracy validation of the three tools: Newbury & Ritchie (2024) tested 263 concentration measurements for 39 elements in 113 materials at 5 keV and found >98% within ±5% RDEV and 82% within ±2% RDEV (newbury2024testingtheaccuracy pages 18-22, newbury2024testingtheaccuracy pages 1-3). At conventional beam energies (E₀ = 20 keV), a database of 122 analyses showed 100% within ±5% RDEV and 89% within ±2% RDEV (newbury2024testingtheaccuracy pages 18-22). The raw analytical total (sum of all constituents) typically falls within 0.98–1.02, serving as an independent quality check (newbury2019electronexcitedxraymicroanalysis pages 3-4). For quantitative compositional mapping, DTSA-II applies the full standards-based quantitative analysis procedure at every pixel of a spectrum image, converting raw intensity maps to true concentration maps that remove artifacts such as the Z-dependent continuum background (goldstein2017compositionalmapping pages 10-13, newbury2019electronexcitedxraymicroanalysis pages 22-26, goldstein2017compositionalmapping pages 13-17). Newbury & Ritchie demonstrated this with a Raney nickel alloy example where false Fe contrast in raw intensity maps was eliminated by quantitative processing (newbury2019electronexcitedxraymicroanalysis pages 26-28, newbury2019electronexcitedxraymicroanalysis pages 22-26).

**Weaknesses/Limitations:** Per-pixel quantitative compositional mapping is computationally intensive and requires high count statistics (~1000+ counts per pixel spectrum) for low-variance wt% maps, which can demand long acquisition times (100–10,000 s depending on pixel density) (newbury2019electronexcitedxraymicroanalysis pages 22-26). Scripting is via Jython (Python on Java), which is functional but less ergonomic than native Python for modern data science workflows. The Java desktop application has a moderate learning curve, particularly for managing the standards archive and understanding the analytical workflow conventions (goldstein2018quantitativeanalysisthe pages 1-4). DTSA-II uses a single default matrix correction model (XPP), without the multi-model comparison capability of CalcZAF.

**Costs:** Free, open source/open access from NIST. Cross-platform (Java). Moderate computational cost for point analyses; higher for per-pixel mapping of large SI datacubes. The learning curve is moderate-to-steep, as the user must understand both the k-ratio protocol concepts and the DTSA-II software interface.

### 2.3 CalcZAF (John Donovan, Probe Software)

**Best use case:** Standalone k-ratio-to-composition matrix correction with the ability to select from and compare multiple φ(ρz)/ZAF correction models on the same data, particularly useful for batch processing of externally measured k-ratios or assessing model-dependent uncertainties (donovan2014electronprobemicroanalysis pages 15-20, korolyuk2009accuracyinthe pages 1-2, donovan2014electronprobemicroanalysis pages 20-23).

**Strengths:** CalcZAF's distinguishing feature is its implementation of multiple matrix correction algorithms — including PAP, XPP, PRZ (PROZA), Armstrong/CITZAF, and others — along with multiple MAC databases (Heinrich, Henke, Chantler) (korolyuk2009accuracyinthe pages 1-2, rickerby1995progressinthe pages 1-4, donovan2014electronprobemicroanalysis pages 20-23). This multi-model capability allows analysts to evaluate the sensitivity of results to the choice of correction algorithm, which is particularly important in challenging analytical situations where the absorption correction is large (e.g., light elements, L-lines, low overvoltage) (rickerby1995progressinthe pages 1-4). Armstrong, Donovan, and Carpenter (2013) specifically documented the use of CalcZAF/TryZAF/CITZAF multi-correction-algorithm programs for estimating uncertainties and improving quantitative analysis of difficult specimens. The Donovan group has also contributed advances in dead-time calibration and k-ratio consensus methods that complement CalcZAF's matrix correction engine (donovan2014electronprobemicroanalysis pages 20-23). For converting externally measured k-ratios (e.g., from EDS or WDS spectrum images) into wt% compositions, CalcZAF can accept k-ratio input directly, making it useful as a post-processing step in hybrid workflows.

**Weaknesses/Limitations:** CalcZAF is Windows-only, which limits its use in cross-platform or cloud-based pipelines. It is primarily a GUI application, with batch capabilities but without the native scripting flexibility of Python or Jython. It is not a spectral front-end — it does not perform peak fitting, background subtraction, or raw spectrum processing. For full quantitative SEM-EDS analysis, it must be paired with another tool (e.g., DTSA-II, vendor software, or custom Python code) that provides peak fitting and k-ratio extraction. Published validation of CalcZAF tends to focus on the accuracy of the matrix correction models themselves rather than end-to-end SEM-EDS analytical accuracy in the DTSA-II RDEV sense.

**Costs:** Open source / freely distributed as part of the Probe Software ecosystem. Low computational burden for k-ratio conversion. Learning curve is moderate for experienced microanalysts but steeper for newcomers unfamiliar with matrix correction theory. Maintenance burden is limited to Windows platform compatibility.

## 3. Specific Questions Addressed

### (a) Per-Pixel Elemental Mapping of Spectrum-Image Datacubes

**eXSpy/HyperSpy** is the best tool for this task. Its native numpy-based datacube handling, PCA/NMF denoising, and full Python ecosystem integration make it the most natural environment for per-pixel processing of large SI datasets (moreira2022quantitativemeasurementof pages 1-7, moreira2023agsurfacesegregation pages 5-10). However, for SEM-EDS bulk quantification, HyperSpy's per-pixel output is limited to Cliff–Lorimer or standardless ratios unless the user builds custom ZAF/φ(ρz) correction workflows. **DTSA-II** can also produce per-pixel quantitative compositional maps via its scripting interface, applying MLLS peak fitting and XPP matrix corrections at every pixel, but this is more computationally intensive and not as naturally datacube-oriented (goldstein2017compositionalmapping pages 10-13, newbury2019electronexcitedxraymicroanalysis pages 22-26).

### (b) Bulk-Sample Standards-Based wt% Quantification of ~0.3–0.5 wt% Mg in AlSi10Mg

**NIST DTSA-II** is the most accurate and validated choice for this scenario. The Mg Kα / Al Kα overlap (Mg Kα at 1.254 keV, Al Kα at 1.487 keV, separated by ~233 eV at an EDS resolution of ~60–70 eV FWHM in this energy range) is a moderate but analytically significant interference when Mg is a minor constituent. DTSA-II's MLLS peak fitting with measured peak references is specifically designed to deconvolve such overlaps and generate a peak-fitting residual spectrum for quality control (newbury2019electronexcitedxraymicroanalysis pages 3-4, newbury2019electronexcitedxraymicroanalysis pages 15-16, newbury2019electronexcitedxraymicroanalysis pages 20-22). The RDEV studies confirm that DTSA-II achieves ±5% relative accuracy for minor constituents in many materials (newbury2024testingtheaccuracy pages 18-22, newbury2024testingtheaccuracy pages 1-3). Donovan's EPMA textbook notes that the mass absorption coefficient for Mg Kα in different matrices (e.g., ~802 vs. ~859 cm²/g in Si, depending on the MAC database) can introduce ~1% variation in results, highlighting the importance of the correct MAC choice — an area where CalcZAF's multi-database comparison can provide additional insight (donovan2014electronprobemicroanalysis pages 20-23).

### (c) CalcZAF's Advantages for K-Ratio-to-Composition Conversion

CalcZAF's standalone k-ratio-to-composition conversion with multiple φ(ρz) model choices offers advantages over DTSA-II's built-in XPP correction in several scenarios: (1) when the analyst wants to assess model-dependent systematic uncertainty by comparing PAP, XPP, PROZA, and CITZAF results on the same k-ratios (korolyuk2009accuracyinthe pages 1-2, rickerby1995progressinthe pages 1-4); (2) when processing k-ratios extracted from external sources (e.g., vendor software, Python pipelines, or WDS measurements) in batch mode; (3) for per-pixel wt% maps where k-ratios have been extracted by one tool (e.g., HyperSpy or DTSA-II) and the user wants to apply a different matrix correction model; and (4) in situations where specific elements or energy ranges are known to be sensitive to the choice of correction algorithm — for example, Rickerby (1995) found that the XPP model gave the least total error when K- and L-lines were combined, while the PAP procedure was generally better for K-lines only (rickerby1995progressinthe pages 1-4). This kind of model comparison is uniquely facilitated by CalcZAF's multi-algorithm framework.

### (d) Accuracy Evidence

- **DTSA-II:** The most extensively documented. Newbury & Ritchie (2019) demonstrated that RDEV spans less than ±5% relative for >95% of EDS analyses of major and minor constituents (newbury2019electronexcitedxraymicroanalysis pages 26-28, newbury2019electronexcitedxraymicroanalysis pages 10-13). At E₀ = 5 keV, >98% of 263 measurements across 39 elements fell within ±5% RDEV, with 82% within ±2% (newbury2024testingtheaccuracy pages 18-22, newbury2024testingtheaccuracy pages 1-3). At E₀ = 20 keV, 89% were within ±2% RDEV (newbury2024testingtheaccuracy pages 18-22). Trace sensitivity extends to 0.001 mass fraction even with severe peak interference (newbury2019electronexcitedxraymicroanalysis pages 26-28).
- **CalcZAF / φ(ρz) models:** Validation is primarily through model-comparison studies. Korolyuk et al. (2009) compared ZAF, PRZ, PAP, and other models, finding that when both absorption and atomic number effects are significant, total error can reach 2–4 rel% (korolyuk2009accuracyinthe pages 1-2). Rickerby (1995) showed that the XPP model gave lower total error than PAP for combined K- and L-line analyses (rickerby1995progressinthe pages 1-4). Armstrong et al. (2013) specifically documented the multi-model comparison approach for estimating uncertainties.
- **HyperSpy/eXSpy:** No published bulk-SEM-EDS accuracy benchmark comparable to the RDEV studies exists. Validation is implicit through its widespread use in STEM-EDS quantification publications (e.g., Moreira et al. 2023 for AuAg nanoparticles using Cliff–Lorimer) (moreira2023agsurfacesegregation pages 5-10), but these are thin-film/nanoparticle contexts rather than bulk SEM samples.

### (e) Scriptability and Automation for Analysis Pipelines

- **eXSpy/HyperSpy (Python):** Best for end-to-end automation. Native Python with numpy, scipy, scikit-learn integration. Jupyter notebooks, CI/CD pipelines, and GPU-accelerated workflows are all straightforward. Widely used in automated STEM-EDS analyses and machine-learning-augmented spectral processing (moreira2022quantitativemeasurementof pages 1-7, moreira2023agsurfacesegregation pages 5-10).
- **DTSA-II (Jython):** Scriptable via Jython, a Python implementation running on the Java Virtual Machine. Capable of automating batch analysis and per-pixel mapping through scripting (goldstein2017compositionalmapping pages 10-13), but the Jython environment is less ergonomic than native Python and lacks access to the full scientific Python stack (numpy C extensions, for example). Suitable for instrument-adjacent automation but less flexible for modern data science pipelines.
- **CalcZAF (Windows GUI/batch):** The least scriptable of the three. Primarily GUI-driven, with some batch processing capability for k-ratio conversion. Not naturally suited to reproducible, scripted pipelines. Best used as a dedicated correction utility in a mixed-tool workflow.

## 5. Recommended Combined Workflow

For the most robust SEM-EDS quantitative analysis pipeline, a combined workflow leveraging all three tools is advisable: use **HyperSpy/eXSpy** for SI datacube ingestion, denoising (PCA/NMF), pixel masking, and region-of-interest extraction (moreira2022quantitativemeasurementof pages 1-7, moreira2023agsurfacesegregation pages 5-10); use **NIST DTSA-II** for standards-based k-ratio extraction with MLLS peak fitting and XPP-corrected quantification, taking advantage of its published accuracy benchmarks (newbury2019electronexcitedxraymicroanalysis pages 3-4, newbury2024testingtheaccuracy pages 18-22, newbury2019electronexcitedxraymicroanalysis pages 1-2); and use **CalcZAF** when you need to convert those k-ratios through multiple φ(ρz) correction models for uncertainty assessment or when comparing against independently measured EPMA k-ratios (donovan2014electronprobemicroanalysis pages 20-23, korolyuk2009accuracyinthe pages 1-2, rickerby1995progressinthe pages 1-4). This combined approach is especially valuable for challenging analyses such as minor Mg in an AlSi10Mg alloy, where the Mg Kα / Al Kα overlap demands careful peak fitting (DTSA-II), the absorption correction sensitivity should be checked across models (CalcZAF), and per-pixel wt% maps need efficient datacube processing (HyperSpy/eXSpy).
